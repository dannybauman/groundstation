Round 1 · Forecasts and the new Zarr stores

1
zarr forecast
field analyst
Input
What is the temperature in Laredo, Texas tomorrow, from the HRRR forecast?
Our read
The search put both forecast stores in front of the question, and the one that is deprecated declined to answer rather than answering from a copy that is going away. HRRR is the forecast store for Laredo (CONUS, 3 km). For the box around the city at 2026-10-26 18:00 UTC it read a mean of 300.3059223090278 K across 225 cells, min 299.53564453125, max 301.09814453125, std 0.36198036404011924. The answer is in kelvin, as the store holds it. The one store here with a tile template is ERA5, and it is history (2m_temperature, ends 2023-01-10), so it can draw a map of a past day, not tomorrow.

Learning → The answer comes back in kelvin. A person asking for tomorrow's temperature wants degrees, and the tool does not convert; the units field says K and the conversion is left to the reader. Also: the stats sel echoes the key as time, not the valid_time that was passed, and the place filter is not applied to curated zarr stores (the note says so), so a place outside CONUS would still list HRRR until the stats call refuses it (the refusal is in the code's coverage check, not in this run).

Round 2 · Finding what covers a place, and when the next look comes

2
discovery filter
humanitarian planner
Input
Which collections cover Efate, Vanuatu, at 10 m or finer?
Our read
The literal question, "optical imagery", returned nothing and said so: the search matches words, and no collection carries that phrase. That is an honest empty, not a statement that nothing exists. Searching "sentinel" with the 10 m cap gives the answer: four Earth Search Sentinel-2 collections and the Planetary Computer one, each declaring gsd 10.0. Searching "imagery" finds a finer option the sentinel query did not surface, the Planet NICFI basemaps at gsd 4.77. Collections that declare no gsd are kept and labelled "resolution unknown (not necessarily coarse)" instead of silently dropped, so Sentinel-1 radar and land-cover products ride along in the list.

Learning → The first phrasing found nothing. A user would type "optical imagery" and get an empty list, and the note is the only hint that different words would work. The tool matches words and not meaning, so the useful answer needed a second and third query. Worth building: a suggestion of nearby terms when the result is empty.

3
next_pass
field team lead
Input
When is the next open-data satellite pass over Efate?
Our read
Five open-data passes in three days. The first optical one is SENTINEL-3B at 2026-10-25 22:48 UTC. The first Sentinel-2 pass, the 10 m imager from the last question, is SENTINEL-2C at 2026-10-26 23:01 UTC, and the first radar one is SENTINEL-1A at 2026-10-28 07:00 UTC, which sees through cloud day or night. A pass is a possible capture, not an acquisition plan: the result is swath geometry from live orbit data, cloud is its own gamble, and the imagery lands in the catalogs hours to a day after. For the richer view the result links EO Predictor (https://developmentseed.org/eo-predictor).

Learning → Nothing broke, but the list is thin for the question. Round 3 · Working from an archive, and the brief

4
archive
offline analyst
Input
Cache a month of Sentinel-2 over Chelan County, then search it with no network.
Our read
Sixty-four Sentinel-2 scenes for the county were written to one parquet file. The proof of the offline claim is the control: with the same dead proxy a live call fails with Connection refused, and the archive search with a bbox returned five scenes. The archive search ran with no network. It carries its own honesty: the result says it is a snapshot as of 2026-10-25, that newer scenes may exist, and that analysis still goes through the live catalog. The recommendation is the same coverage-versus-cloud trade as before: S2C_10UFU_20261023_0_L2A is 8.8687% cloud and covers 49.7%, the clearest scene covers 16.5%, and none of the five returned covers the county alone.

Learning → "Offline" held only after the place name was swapped for a bbox. With place="Chelan County" the archive search still geocodes first, and the geocoder is a live call: it failed with Connection refused under the dead proxy. An archive search is offline only when the caller already has the bbox. Worth fixing: cache the archive's own extent so a place name can resolve against it. Also, the archive's own note sends analysis back to the live catalog, so a plane with no network can find a scene but not read it.

conditions brief
emergency desk
Input
Brief me on Chelan County, including smoke.
Our read
The brief and the smoke frame are two separate calls in this tree. conditions_brief returned the dryness, wind, events, latest look and next passes, and no smoke and no artifact. The smoke frame comes from smoke_forecast: 0.5 µg/m³ now and 0.1 µg/m³ for 2026-10-26T18:00Z, on a scale where under 5 is clear. Smoke is not a concern at this moment and it is model guidance, not a measurement: NOAA HRRR, and the tool says its plume edges can be off by hours and miles. The map shows the forecast frame as a layer.

Learning → The brief did not carry the smoke frame, and it wrote no html. The smoke frame and the shareable page live in briefing/brief.py (which calls an LLM and the tiler), not in conditions_brief, so a plain call to the function cannot reproduce the page the doc describes. I ran the two pieces the function-level API offers and drew the map with render_map. Also noted: the dryness block reads days_since_last_rain null beside a signal saying no rain over 1 mm in 14 days, correct but easy to misread.
